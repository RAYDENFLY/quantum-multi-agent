## 1. Executive Summary

This audit evaluates the statistical quality, causal integrity, collinearity, and lookahead leakage risks of all 55 base technical indicators and the 57-column feature matrix generated by `FeatureEngine` (`src/quantum/features/engine.py`).

### Key Audit Conclusions
1. **Mathematical Causality**: All 55 base indicators are strictly causal at prediction time $T_{\text{predict}} = T_{\text{close}}$. Indicators operate strictly on closed historical candle arrays. No indicator references future bar data ($t+1, \dots$).
2. **Multi-Timeframe Causal Invariant**: The `MultiTimeframeJoiner` strictly enforces $T_{\text{HTF.close}} \le T_{\text{LTF.open}}$ via backward as-of joining. No in-flight higher-timeframe bar is ever joined into lower-timeframe records.
3. **Warm-Up Behavior & NaN Demarcation**: Exactly 49 features produce initial NaNs due to rolling window warm-up periods. The maximum warm-up requirement across the entire feature suite is exactly 200 bars (`ema_200_slope`). After index 200, exactly 0 NaNs remain across all features.
4. **Zero Infinite Values**: Evaluated across 2,000 real market candles and 105,120 synthetic benchmark candles, exactly 0 positive or negative infinite values were generated. Safe epsilon protection ($\varepsilon = 10^{-12}$) prevents division-by-zero errors.
5. **Collinearity and Non-Stationarity Risks Identified**:
   - **Perfect Redundancy**: `simple_return`, `log_return`, and `pct_change` have pairwise correlation $r = 1.0000$. They are scalar re-scalings of each other.
   - **Nominal Price Non-Stationarity**: Features expressing unscaled nominal USDT price levels (`ema_9`, `ema_21`, `ema_50`, `ema_100`, `ema_200`, `bb_middle_20`, `bb_upper_20`, `bb_lower_20`, `donchian_high_20`, `donchian_low_20`) have cross-correlations exceeding $r > 0.98$ and are non-stationary. They are classified as `CONDITIONALLY SAFE` and must be excluded or transformed into scale-invariant distance metrics prior to ML training.

## 3. Comprehensive Leakage Risk Audit

### 3.1 Rolling Window Alignment Audit
- **Inspection:** Inspected window indexing in `src/quantum/features/engine.py` and `src/quantum/features/indicators.py`.
- **Finding:** Rolling computations strictly use past-looking windows `[t - window + 1 : t + 1]`. For example, `rolling(window=20).mean()` evaluates bars $t-19$ to $t$.
- **Donchian Pre-Shift Guard:** In `compute_donchian_channels`:
  ```python
  s_high = pd.Series(high).shift(1)
  s_low = pd.Series(low).shift(1)
  donchian_high = s_high.rolling(window=period, min_periods=period).max().to_numpy()
  ```
  The input series is explicitly shifted by 1 bar before taking the rolling maximum, ensuring that `donchian_high_20[t]` strictly represents $\max(H_{t-20 : t-1})$. Current bar $t$ is never included in the channel boundary against which breakout is measured.
- **Verdict:** **SAFE** (Zero forward leakage).

### 3.2 Multi-Timeframe Alignment & Causal Invariant
- **Mathematical Invariant:** $T_{\text{HTF.close}} \le T_{\text{LTF.open}}$.
- **Inspection:** Inspected `MultiTimeframeJoiner.join_htf_features` in `src/quantum/features/multitimeframe.py`:
  ```python
  merged = pd.merge_asof(
      merged,
      htf_subset,
      left_on="open_time_ms",
      right_on="_htf_join_close",
      direction="backward",
  )
  ```
- **Finding:** `merge_asof` with `direction="backward"` joins each LTF bar opening at $T_{\text{LTF.open}}$ with the latest HTF bar whose `close_time_ms` is $\le T_{\text{LTF.open}}$.
- **Example:** For a 5-minute candle opening at 12:00:00 (close at 12:04:59):
  - The 1-hour candle covering 11:00:00 to 11:59:59 closed at 11:59:59.999 ($< \text{12:00:00}$). Its features are joined.
  - The 1-hour candle covering 12:00:00 to 12:59:59 closes at 12:59:59 ($> \text{12:00:00}$). It is strictly excluded.
- **Verdict:** **SAFE** (Zero lookahead leakage).

### 3.3 Train/Test Preprocessing Contamination
- **Audit:** Any scaling, normalization, or feature selection applied across the entire dataset before splitting contaminates the training set with test set distribution parameters (mean, variance, min/max).
- **Rule for Phase 5.1:** Normalization scalers (e.g. `StandardScaler`, `RobustScaler`) must be fit strictly on training fold observations and applied (`transform` only) to validation and test folds.

## 4. Feature Quality Classification & Actionable Remediations

### Summary of Classifications
- **SAFE (38 Features):** Scale-invariant, stationary, causal, bounded or fractional features suitable for immediate use in machine learning models.
- **CONDITIONALLY SAFE (17 Features):** Mathematically causal, but express raw nominal price levels or unnormalized currency scales. They must be handled as follows:
  1. **Nominal Moving Averages & Bands (`ema_9`, `ema_21`, `ema_50`, `ema_100`, `ema_200`, `bb_middle_20`, `bb_upper_20`, `bb_lower_20`, `donchian_high_20`, `donchian_low_20`):** Exclude from direct feature input to ML models. Use their stationary distance equivalents (`price_dist_ema_*`, `bb_pct_b_20`, `bb_width_20`, `donchian_breakout_dist`) instead.
  2. **Nominal MACD Values (`macd_line`, `macd_signal`, `macd_hist`):** Normalize by dividing by $C_t$ before training to make them scale-invariant across price regimes.
  3. **Nominal Volume Levels (`vol_sma_20`, `quote_vol_sma_20`):** Use relative volume features (`rvol_20`, `quote_rvol_20`) instead.
  4. **Exact Duplicates (`simple_return`, `pct_change`):** Drop `simple_return` and `pct_change`; retain `log_return`.
- **UNSAFE (0 Features):** Zero non-causal or leaking features detected in the implementation.
- **UNVERIFIED (0 Features):** All 55 features fully audited and verified.
