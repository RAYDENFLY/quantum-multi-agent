## 4. DETAILED TECHNICAL AUDIT ACROSS SEVEN ACCEPTANCE CRITERIA

### Dimension A: Causal Execution

#### Criterion A1: Entry Reference vs Execution Fill Guarantee
- **Finding:** In `src/quantum/agents/sniper.py:L70-L85`, `SniperAgent` constructs trade proposals assuming execution at `bid1_price` or `ask1_price`. No component implements the execution assumption of Track 2 ($P_{\text{entry,ref}} = \text{open}[i+1]$). Furthermore, treating $\text{open}[i+1]$ as a guaranteed fill without modeling opening gaps or execution slippage would introduce optimistic fill bias.
- **Status:** `NOT_IMPLEMENTED`
- **Severity:** CRITICAL
- **Required Action:** Implement a causal order execution model in `src/quantum/backtesting/engine.py` that treats $\text{open}[i+1]$ as the reference price and adds parameterized execution deviation $\delta_{\text{exec}}$.

#### Criterion A2: Intrabar Same-Bar TP/SL Collision Handling
- **Finding:** In `src/quantum/features/labeling.py:L218-L225`, when both upper and lower barriers are breached within the same 5m candle, the sample is labeled `AMBIGUOUS_INTRABAR_DOUBLE_TOUCH` (`label = -2`) and excluded from machine-learning datasets. In an economic backtest, ambiguous collisions cannot be dropped; doing so would introduce severe survivorship and selection bias.
- **Status:** `PASS_WITH_LIMITATIONS` (for labeling); `NOT_IMPLEMENTED` (for backtesting).
- **Severity:** HIGH
- **Required Action:** The backtesting engine must implement a deterministic, conservative collision policy: assume Stop-Loss is triggered first whenever both barriers are touched within the same bar, unless verifiable higher-frequency tick data proves otherwise.

#### Criterion A3: Lookahead Bias in Feature Computation
- **Finding:** In `src/quantum/features/labeling.py:L70-L80`, volatility $\sigma_t$ is computed using `ddof=1` sample standard deviation over past rolling windows (`volatility_lookback = 20`) strictly using past close returns. In `src/quantum/features/temporal_split.py`, partition boundary enforcement prevents forward horizon leakage into subsequent folds.
- **Status:** `PASS`
- **Severity:** LOW

### Dimension B: Price and PnL Accounting

#### Criterion B1: Two-Legged Entry/Exit Notional Scaling
- **Finding:** While [`PHASE_5_5_0_8_LONG_SHORT_ACCOUNTING_AUDIT.md`](file:///d:/quantum-multi-agent/docs/research/phase_5_5_0_8/PHASE_5_5_0_8_LONG_SHORT_ACCOUNTING_AUDIT.md) formally proves that exit notional scales as $N_{\text{exit}} = N_{\text{entry}}(1 + d \cdot R_{\text{gross}})$, resulting in fee asymmetry ($15.1125$ bps for winners vs $14.8875$ bps for losers at $15$ bps base rate), there is **ZERO executable Python code** implementing this formula.
- **Status:** `NOT_IMPLEMENTED`
- **Severity:** CRITICAL
- **Required Action:** Build `src/quantum/backtesting/accounting.py` implementing exact two-legged notional scaling and signed transaction fee accounting.

#### Criterion B2: Realized vs Unrealized PnL and Partial Exits
- **Finding:** In `src/quantum/agents/contracts.py:L116-L141`, `TrackedPosition` tracks quantities (`initial_quantity`, `remaining_quantity`, `tp1_filled_quantity`, `tp2_filled_quantity`), but contains zero financial PnL fields. In `BankerAgent` (`src/quantum/agents/banker.py:L120-L240`), partial TP1 fills reduce remaining quantity and ratchet stops, but realized PnL is neither computed nor stored.
- **Status:** `NOT_IMPLEMENTED`
- **Severity:** CRITICAL
- **Required Action:** Implement position accounting tracking realized cash flows upon partial/full fills and mark-to-market unrealized PnL on remaining quantities.

#### Criterion B3: Position Inventory Method (Average Cost Basis vs FIFO)
- **Finding:** The repository contains no inventory matching logic. For Track 2 (single-trade, non-overlapping 12-bar holding), inventory matching is trivial because positions do not scale or aggregate. However, for multi-position portfolio simulation, the policy is undefined.
- **Status:** `NOT_APPLICABLE` for Track 2; `NOT_IMPLEMENTED` for Track 3 portfolio scaling.
- **Severity:** MEDIUM
- **Required Action:** Explicitly restrict Track 2 execution specifications to single-position non-overlapping trades, deferring ACB/FIFO selection to DEC_05.

### Dimension E: Simulation Clock (CRITICAL BLOCKER)

#### Criterion E1: Wall-Clock Dependency in RiskAgent Gate 1
- **Finding:** In [`src/quantum/agents/risk.py:L102-L121`](file:///d:/quantum-multi-agent/src/quantum/agents/risk.py#L102-L121):
  ```python
  now_ms = int(time.time() * 1000)
  signal_age_ms = now_ms - context.snapshot_timestamp_ms
  if signal_age_ms <= 15_000:
      checks_passed.append("SIGNAL_FRESHNESS")
  else:
      veto_reasons.append(f"VETO_STALE_SIGNAL: age {signal_age_ms}ms > 15000ms")
  ```
  `now_ms` is obtained directly from system wall clock `time.time()`. If a historical candle from 2024 or 2025 is evaluated, `signal_age_ms` is millions of milliseconds, causing Gate 1 to **VETO 100% OF HISTORICAL PROPOSALS WITH `VETO_STALE_SIGNAL`**.
- **Status:** `FAIL`
- **Severity:** CRITICAL
- **Required Action:** Add an optional `eval_timestamp_ms: Optional[int] = None` field to `RiskInput`. In `RiskAgent.evaluate()`, set `now_ms = input_data.eval_timestamp_ms if input_data.eval_timestamp_ms is not None else int(time.time() * 1000)`.

#### Criterion E2: Wall-Clock Dependency in RiskAgent Gate 4
- **Finding:** In `src/quantum/agents/risk.py:L173`, loss streak cooldown evaluation computes:
  ```python
  elapsed_loss_cooldown = now_ms - input_data.last_loss_timestamp_ms
  ```
  Using system wall clock causes historical loss timestamps to appear permanently expired or invalid.
- **Status:** `FAIL`
- **Severity:** CRITICAL
- **Required Action:** Resolve via the simulated clock injection described in E1.

#### Criterion E3: Wall-Clock Dependency in BankerAgent
- **Finding:** In [`src/quantum/agents/banker.py:L312-L325`](file:///d:/quantum-multi-agent/src/quantum/agents/banker.py#L312-L325):
  ```python
  now_ms = int(time.time() * 1000)
  ```

  During historical replay, `BankerAgent.evaluate()` will permanently freeze in `SAFE_MONITORING: market price is stale`.
- **Status:** `FAIL`
- **Severity:** HIGH
- **Required Action:** Add `eval_timestamp_ms` to `BankerInput` and use it as `now_ms` when provided.

**Conclusion:** Running an economic backtest at this stage is physically impossible without engineering remediation. Attempting to force execution would produce empty results (all trades vetoed) or completely fictitious numbers.
